## Chapter 1: Exploratory Data Analysis and Data Quality Triage — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | MCAR vs MAR vs MNAR — key distinguishing question? | MCAR: missingness unrelated to any variable (observed or not). MAR: missingness depends only on OBSERVED variables. MNAR: missingness depends on the UNOBSERVED value itself. Exam tip: MNAR requires a missingness indicator or selection model — simple imputation is invalid. |
| 2 | Standard IQR outlier multiplier vs extreme outlier multiplier? | Standard outlier: k = 1.5 × IQR. Extreme outlier: k = 3.0 × IQR. Exam swaps these two values as a common trap. |
| 3 | Common z-score threshold for flagging outliers? | \|z\| > 3 is the conventional threshold (about 0.3% of a normal distribution). Assumes roughly normal data — invalid for skewed distributions. |
| 4 | SMOTE default k_neighbors parameter (imbalanced-learn)? | Default k_neighbors=5. Controls how many nearest minority-class neighbors are used to interpolate synthetic samples. Too high a k can generate unrealistic samples in sparse regions. |
| 5 | sklearn syntax for cost-sensitive class weighting? | `LogisticRegression(class_weight='balanced')` — automatically weights classes inversely proportional to their frequency. No synthetic data created, no rows dropped. |
| 6 | SMOTE vs random undersampling vs class weights — when to pick each? | SMOTE: need more minority signal, can tolerate synthetic data. Undersampling: majority class is huge and redundant, can afford to lose data. Class weights: want to keep all data unchanged, cheapest computationally, no new samples. |
| 7 | Isolation Forest vs Z-score vs IQR — when to use each? | Z-score/IQR: univariate, assumes roughly normal/simple distributions, fast, interpretable. Isolation Forest: multivariate, non-linear, correlated features, handles high dimensions without distributional assumptions. |
| 8 | Correct pipeline order to avoid train-test contamination? | 1) Split data first. 2) Fit scaler/imputer/encoder ONLY on train fold. 3) Transform both train and test using train-fit parameters. Use sklearn Pipeline + cross_val_score to enforce this automatically. |
| 9 | Target leakage vs train-test contamination — what's the difference? | Target leakage: a FEATURE encodes information only available after/because of the target outcome (e.g., 'refund_issued' predicting 'is_fraud'). Train-test contamination: preprocessing statistics (scaler mean/std, imputed values) computed using test data leak into training. |
| 10 | Log transform vs Box-Cox vs Yeo-Johnson — when to use each? | Log: strictly positive, simple right-skew fix. Box-Cox: strictly positive data, finds optimal lambda automatically. Yeo-Johnson: handles zero and negative values, generalizes Box-Cox. |
| 11 | Computational/data-volume cost ranking: SMOTE vs undersampling vs class weights? | Highest cost: SMOTE (increases dataset size, more training time). Medium: undersampling (smaller dataset, faster but less data). Lowest cost: class weights (same dataset size, just reweighted loss function, no extra rows). |
| 12 | Correlation vs causation — what must you check before inferring causation? | Rule out confounding variables, reverse causality, and coincidence/small-sample spurious correlation. Exam tip: a plausible confounder that independently drives both variables is the most commonly tested explanation for non-causal correlation. |
